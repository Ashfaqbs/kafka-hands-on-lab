### **🔥 Kafka Producer & Consumer Config for 1000 TPS**  

For **1000 transactions per second (TPS)**, you need optimized Kafka configurations for **high throughput** and **low latency**. Here's how your **Spring Boot Kafka producer and consumer configs** should look:  

---

## **🔹 Producer Config (High Throughput)**
```yaml
spring:
  kafka:
    producer:
      bootstrap-servers: localhost:9092
      acks: 1  # Leader acknowledgment for better speed
      batch-size: 65536  # 64KB batch size
      linger-ms: 5  # Small delay to batch records together
      buffer-memory: 33554432  # 32MB buffer for producer
      compression-type: lz4  # Fast and efficient compression
      key-serializer: org.apache.kafka.common.serialization.StringSerializer
      value-serializer: org.apache.kafka.common.serialization.StringSerializer
```

### **🔍 Explanation:**
- `acks: 1` → Fastest acknowledgment (only leader confirms).  
- `batch-size: 65536 (64KB)` → Allows batching multiple messages.  
- `linger-ms: 5` → Small delay to increase batching.  
- `compression-type: lz4` → Efficient compression to reduce bandwidth usage.  
- `buffer-memory: 32MB` → Avoids throttling when sending high-volume messages.  

---

## **🔹 Consumer Config (High Throughput)**
```yaml
spring:
  kafka:
    consumer:
      bootstrap-servers: localhost:9092
      group-id: high-tps-group
      enable-auto-commit: false  # Manual commit for precise control
      fetch-min-bytes: 1048576  # 1MB minimum fetch size to reduce network calls
      fetch-max-wait-ms: 500  # Wait 500ms to fetch more records
      max-poll-records: 1000  # Process 1000 records at a time
      auto-offset-reset: latest
      key-deserializer: org.apache.kafka.common.serialization.StringDeserializer
      value-deserializer: org.apache.kafka.common.serialization.StringDeserializer
```

### **🔍 Explanation:**
- `enable-auto-commit: false` → We commit manually for better throughput.  
- `fetch-min-bytes: 1MB` → Fetch larger chunks at a time to reduce network calls.  
- `fetch-max-wait-ms: 500` → Wait longer to get more messages in a single fetch.  
- `max-poll-records: 1000` → Allows processing 1000 records per poll.  

---

## **🔹 Topic Config (High Throughput)**
```yaml
spring:
  kafka:
    admin:
      properties:
        topic:
          name: high-tps-topic
          partitions: 10  # More partitions for parallel processing
          replication-factor: 2  # Minimum for fault tolerance
```

### **🔍 Explanation:**
- `partitions: 10` → More partitions allow multiple consumers to read in parallel.  
- `replication-factor: 2` → Ensures availability if a broker fails.  

---

## **💡 Additional Tuning for 1500+ TPS**
If you're scaling to **1500 TPS or 2000 TPS**, increase:  
- **`partitions` →** Scale to **15-20 partitions**.  
- **`batch-size` →** Increase to **128KB**.  
- **`buffer-memory` →** Increase to **64MB**.  
- **`max-poll-records` →** Increase to **2000** if needed.
